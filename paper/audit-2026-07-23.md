## E. Code items (added 2026-07-27, from the flux-tilt discussion)

32. **LEVY_LOG_MEAN has a closed form: 1/(α−1).** The comment at
    simulate.py L118 ("no closed form in this generator's scale
    convention") is wrong — in the UM convention (the |α−1| inside the
    CMS factor) the secants cancel: log⟨e^{θγ₀}⟩ = θ^α/(α−1) exactly
    (float64 MC: 1.25075 vs 1.25 at α=1.8; matches at 1.5 and 1.95 too).
    One-liner: `LEVY_LOG_MEAN = 1.0 / (FLUX_ALPHA - 1.0)`; the current
    8M-draw value 1.2510 is 0.08% high. The supplement now states the
    analytic constant with the derivation (S1 flux advance, marked
    movable to the appendix) plus a % NOTE tied to this item.
33. **_extremal_levy float32 corner: spurious right-tail draws.** Where
    cos(φ−α(φ−φ₀)) crosses zero, float32 absolute error (~6e-8) swamps
    the true value — occasionally flipping its sign into the 1e-12 clip —
    and the ^{−(α−1)/α} power amplifies the error into impossible
    positive draws (α=1.5: +64 in 30M where the true max is ~8; α=1.95:
    +259; the true right tail is stretched-exponential, dead by ~+10).
    At production α=1.8: 0 spurious draws in 360M across 12 seeds —
    latent, not active. **Root cause found (your "check the existing
    clipping" call): eps mismatch in the port.** scaleinvariance's
    `_extremal_levy_core` clips at a precision-scaled eps (~100× machine
    eps: 1e-6 in its float32 default) and is clean at all α in both
    precisions (verified, 30M draws each); STEAM's port kept the clip
    structure but hardcoded the float64-scale `eps = 1e-12` into the
    float32 pipeline, letting garbage cosines in the 1e-12–1e-8 range
    through the negative power. Verified fix: `eps = np.float32(1e-6)`
    in `_extremal_levy` — identical port code is then clean at 1.5/1.8/
    1.95 (max ~7, log⟨e^γ⟩ exact to 4 digits). The larger eps also caps
    the legitimate far-negative tail at smaller magnitude, which is
    invisible through exp(γ) (both map to multiplier −1). One-line edit,
    pending your go (mid-audit).
34. **Density compensation is NOT invariance-preserving (measured
    2026-07-27, calibration re-fit sweep).** Within each cascade density
    the c^α collapse is essentially perfect (free exponents 1.787 / 1.810
    / 1.828 at n_c = 1/2/4, R² ≥ 0.999), but across densities the
    amplitude scales as **A ∝ 1/n_c** (A(2)/A(1) = 0.554, A(4)/A(1) =
    0.245): realized per-octave intermittency equals ONE compensated
    class's worth, as if the n_c classes within an octave do not
    accumulate independent K(2). With the n_c^{−1/α} compensation the
    α-stability argument predicts exact invariance — the measurement
    contradicts the appendix/supplement claim as stated. Untested
    hypothesis worth one targeted check: n_c× more zoom_trilinear hops
    per octave repeatedly smooth the flux (interpolation damping);
    envelope overlap between 2^{1/n_c}-spaced classes is the other
    candidate. Production runs n_c = 1, so the C20 mapping is unaffected
    — but the density-invariance sentence needs weakening or the
    mechanism fixed before anyone runs n_c > 1.
